# Интерфейс и сцена

> [!abstract]
> Интерфейс должен показывать исследовательскую дискуссию как наглядную сцену, почти как интерактивную визуальную новеллу. Это часть продукта, а не декоративная оболочка.

## Базовый UX-принцип

> [!important]
> Не делать обычный чат.

Пользователь должен видеть:

- кто сейчас говорит;
- кто возражает;
- как меняется гипотеза;
- на каких источниках основаны реплики;
- как спор переходит в независимую оценку;
- как судья выносит итог.

## Целевая композиция экрана

### Левая панель

- список исследовательских сессий;
- история обсуждений;
- быстрый переход между кейсами.

### Центральная сцена

- текущая гипотеза;
- участники debate loop;
- анимированное развитие спора;
- фиксация переходов `v1 -> v2 -> v3`.

### Блок оценки

- evaluators;
- judge;
- итоговые метрики и приоритет.

### Правая панель

- дополнительные агенты;
- критерии оценки;
- связанные evidence и вложения.

### Нижняя зона

- поле постановки задачи;
- загрузка файлов;
- запуск анализа;
- уточнение пользовательских ограничений.

## Сценарная драматургия

В целевом UX должны быть заметны:

- появление первичной гипотезы;
- “вход” Защищающего;
- резкое возражение Атакующего;
- жёсткая проверка Производственника;
- переход к независимым evaluators;
- появление Судьи с вердиктом.

## Что обязательно показать пользователю

- evidence, которые реально использовались;
- противоречия между источниками;
- историю правок гипотезы;
- различие между debate и evaluation;
- финальную рекомендацию и next steps.

## Что уже видно в текущем prototype UI

Сейчас frontend уже визуализирует направление продукта:

- левую колонку с сессиями;
- debate stage с `Защищающим`, `Атакующим`, `Производственником`;
- evaluation stage с несколькими evaluators и `Судьёй`;
- правую палитру агентов;
- нижний composer и вложения.

> [!warning]
> Это пока визуальный прототип на моках, а не рабочий продуктовый контур.
