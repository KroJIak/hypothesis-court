# User Flow

## Канонический сценарий

1. Пользователь создаёт исследовательскую сессию.
2. Формулирует KPI, ограничения и контекст задачи.
3. Загружает материалы.
4. Изучает собранный evidence pack.
5. Получает первичную гипотезу.
6. Наблюдает debate loop и версионность гипотезы.
7. Изучает независимую оценку.
8. Получает verdict judge и список первоочередных проверок.

## Flow

```mermaid
flowchart LR
    A[Research brief] --> B[Source upload]
    B --> C[Evidence pack]
    C --> D[Hypothesis v1]
    D --> E[Debate scene]
    E --> F[Evaluation panel]
    F --> G[Judge verdict]
    G --> H[Next checks]
```

## Что пользователь видит на каждом шаге

| Шаг | Что видит пользователь | Зачем это нужно |
| --- | --- | --- |
| Intake | KPI, ограничения, описание контекста | Сессия остаётся привязанной к реальной исследовательской задаче |
| Evidence | Поднятые документы, фрагменты и сигналы | Видно, из чего родилась гипотеза |
| Hypothesis | Формулировку и механизм влияния | Понятно, что именно обсуждают агенты |
| Debate | Реплики ролей и правки версий | Видно, как гипотеза усиливается и очищается |
| Evaluation | Независимые критерии | Риск, стоимость и ценность не смешиваются |
| Verdict | Итоговый приоритет и первый шаг проверки | Решение готово к практическому действию |

## Базовые сущности интерфейса

- `Research Session`
- `Source Document`
- `Evidence Item`
- `Hypothesis Version`
- `Debate Round`
- `Evaluation Result`
- `Judge Verdict`

## Пользовательская ценность траектории

> [!tip]
> Пользователь видит не только финал, но и историю созревания гипотезы: от evidence до версии, которая проходит через спор и оценку.
