# Роадмап

> [!abstract]
> Ниже не “список всех задач мира”, а последовательность, в которой проект логично собирать без потери продуктового смысла.

## Этап 1. Скелет продукта

- Зафиксировать документацию как единый source of truth.
- Держать frontend, backend и nginx в рабочем состоянии как базовую платформу.
- Согласовать канонический сценарий: KPI + документы -> гипотеза -> debate -> evaluation -> judge.

## Этап 2. Backend MVP

- Добавить сущности исследования, документов и сессий анализа.
- Сделать API для загрузки материалов и запуска анализа.
- Реализовать простой retrieval по чанкам.
- Сгенерировать первую структурированную гипотезу.

## Этап 3. Агентный контур

- Добавить loop из `Защитника`, `Атакующего` и `Производственника`.
- Ограничить цикл максимум тремя раундами.
- Хранить версии гипотезы после каждой итерации.

## Этап 4. Независимая оценка

- Добавить стандартные evaluation-роли: `Finance` и `Risk`.
- Разрешить дополнительные пользовательские критерии.
- Передавать их выводы судье в структурированном виде.

## Этап 5. Объяснимый UX

- Показать сцену спора в пошаговом виде.
- Показать evidence, ссылки на источники и историю изменений гипотезы.
- Развести по интерфейсу debate, evaluation и final recommendation.

## Этап 6. Усиление качества

- Улучшить retrieval и evidence layer.
- Добавить валидацию схем ответов LLM.
- Усилить трассировку и диагностируемость пайплайна.

## Контрольные точки

> [!check]
> Каждый следующий этап имеет смысл только если предыдущий уже даёт наблюдаемый и объяснимый результат.

- После этапа 2 система уже должна выдавать первую гипотезу.
- После этапа 3 система уже должна уметь её критиковать и дорабатывать.
- После этапа 4 система уже должна уметь ранжировать гипотезу по критериям.
- После этапа 5 продукт уже должен выглядеть как именно **Hypothesis Court**, а не как generic AI dashboard.
